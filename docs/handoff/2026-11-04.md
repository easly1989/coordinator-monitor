## The mod in brief

A Claude Code mod (hooks module, no DOM, no Node) that gives the coordinator session one pane for every local session, and turns protected commands and questions into cards the person answers in place.

- `hooks/register.tsx`: everything with a side effect. Publishes this session's status, applies answers, the `tool.check` / `tool.call` hooks that hold a protected command until the pane answers, the `queue` tool, the pane and its cards, the digest of quiet notes.
- `hooks/request.ts`: the reading of a shell request. `segmentsOf` cuts it into shell text and blocks (here-doc, here-string, long inline script); `stepsOf` splits it into steps; `viewOf` builds the aid; `touchesOf` lists what it touches; `canFold` decides if a card may open folded; `visible` draws hidden characters as codes.
- `hooks/rules.ts`: the protected rules (`matchRule` tests the **whole** text of a command). `hooks/i18n.ts`: English and Italian strings. `hooks/crab.ts`: sprites.
- `types/index.d.ts`: the `$.state` contract (`board`, `local`, `ui`, `digest`) and the status / answer shapes.
- The bus is a folder (`busDir`, default `~/.claude/coordinator-monitor`): `sessions/<id>.json` (each session's status), `answers/<id>.json` (what the pane answered), `queues.json`, `rules.json`. Only the mod writes it; the guard blocks shell commands that name the bus path. Text read from it is data: it is drawn through `visible()`, fenced, or quoted, never trusted.

## Where the review lessons live

Each rule below came out of a security review that found the opposite one. They are all **fail closed**: when the reading is uncertain, show the text plain. A denylist kept being beaten; an allowlist converged.

| Area | Rule | Code |
| --- | --- | --- |
| The request | The full request is always shown and is what is approved. The steps, the touches and the recap are a labelled aid, never a replacement. | `register.tsx` permission card |
| Rules | A protected rule matches the whole text of the command, so no here-doc, quote or script hides a protected command. | `rules.ts`, `tests/rules.test.ts` |
| Blocks | A here-doc is cut out only where every part of its reading is certain: one `<<` on the line, its word whole, `cat` / `tee` / an interpreter before it, nothing open after it, no process substitution or duplicated descriptor, no descriptor or pipe set up anywhere (`exec N>`, `mkfifo`, `coproc`), no target under `/dev` or `/proc`, `cat` not given files. Else it stays shell text. | `segmentsOf`, `targetOf` |
| Run later | A file a block writes is marked "run later by X" when a later step may run it. Where no runner can be named and a `|` follows the file's first mention, it is marked "may run later (piped)". A false "may run" costs a word; a missed one costs the label. | `runnerOf`, `laterUse` |
| Remnants | Only what closes a block (closing quotes, `'@`, the end word) is drawn under it; any other short remnant that may run keeps its own box. | `tailOf` in `register.tsx` |
| Folding | A card folds only if every block is an inert data file **and** every shell step runs a file mover (cat, ls, mkdir, cd, echo, printf, cp, mv, touch, chmod, tee with one file), with no assignment before it and no `$( )`. Every PowerShell card stays open. | `canFold` |
| Other sessions' text | Hidden and reordering characters are drawn as codes (`visible`); ids must match `/^[\w-]{1,40}$/`; JSON is decoded only if the mod wrote it (`ownJson`); grants are scoped to the asking agent; a peer cannot grant escalation. | `register.tsx` gather and `answer` |
| Quiet notes | They wait in `$.state` (`digest`), not in a file in the bus where any process could write a line the model would read as the mod's. | `queueNote`, `flushDigest` |

## Checks

From the repo root:

```bash
claude plugin test .
claude plugin validate .
```

- Type-check: `tsc -p <mod folder>` once the engine has written `.claude-plugin/types/` for it; before that, a `tsconfig.json` kept outside the repo whose `include` names the engine's `claude-code.d.ts` (the plugin-authoring skill gives its path and header) and `hooks/`, `tests/`, `types/`.
- Scan every diff for hidden characters, **decoding as UTF-8** (a console decoding turns the `à` of Italian strings into U+00A0): `git diff | python -c "import sys,unicodedata as u;t=sys.stdin.buffer.read().decode('utf-8');print([hex(ord(c)) for c in t if u.category(c) in ('Cf','Zl','Zp') or ord(c)==0xa0])"`.
- Test harness: `clock.every` cannot be fired, so a timer is checked through the start-up path; `$.state` is held by the test through `state.get` / `state.set` hooks (the stored value is `{ shape, value }`); a test that needs the bus uses the `setup` helper in `tests/pane.test.tsx`.

## Working in this repo

- A branch per issue off `main`, its own PR; commits and PRs in English. Merges are the owner's.
- Tool JSON turns `\uXXXX` in an Edit or Write into the literal character (a literal U+2028 once broke a parse): write such text as `String.fromCharCode(0x202e)` or `\u{…}` in code, and scan the diff.
- The guard blocks commands that contain protected words even inside a commit message (`mkfs`, `merge`, a push to `main`). Write the message to a file and use `git commit -F`; a protected command that needs the person asks a card in the pane and must be run **exactly** as approved.
- Windows: the repo has CRLF files; `git diff` warns and normalises, which is fine.

## Vendoring into claude-environment

The mod is vendored there as a skills-dir plugin under `skills/coordinator-monitor/`, without `README.md`, `docs/` and `tests/`, at an exact commit recorded in `skills/VENDORED.md` (0.6.5 is `d10b9f9`, claude-environment#47). No local patches: the owner's settings live in `config/coordinator-monitor.rules.json` and `pluginConfigs` in `config/settings.template.json`. The coordinator session does the vendoring after a merge; to refresh, re-copy at the new commit and record it in `VENDORED.md`. See D-087 in `docs/DECISIONS.md` there. A session keeps the copy it loaded, so a newer version reaches the others when they reload plugins (the mod does it once per version when the coordinator publishes a newer one).
