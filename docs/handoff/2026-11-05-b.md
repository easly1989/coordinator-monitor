# Handoff, 2026-11-05 (b), 0.6.8

Follows `docs/handoff/2026-11-05.md`. `main` is at 0.6.8 (2bffe0b): #28, #29, #30 and #31 are merged and released. No issue is open and no branch is open.

## What changed in 0.6.8

- **#25, empty "Domande per te"** (#28). In `turn.complete` (`hooks/register.tsx`), a heading with an empty body, or only a "nothing to ask" line (`NO_QUESTIONS` in `hooks/i18n.ts`: Nessuna…, None…), is handled as if the heading were absent, so the turn gets its normal report card. Any other body is the QUESTIONS card as written (numbered or not).
- **#26, closed sessions leave the pane** (#29). In `gather`: an ended session goes 5 minutes after its last heartbeat (`ENDED_GRACE_MS`). It stays while a planned-task queue is held for it (any age), and up to `ENDED_KEEP_MS` (1 h) while it holds a card that awaits an answer; report cards do not count.
- **#23, digest follow-ups** (#30). `flushDigest` resets `deliveredSeq` when `d.seq` falls below it; a throwing `$.prompt.submit` in `applyAnswers` queues that answer urgent and the batch goes on, with a toast (`answerLostToast`) if it cannot be queued either.
- **#24** was closed without code: Carlo decided `cp` and `mv` stay foldable.

## Noticed, not filed

- Status files of ended sessions are never deleted: `$.fs` has no delete (checked in the engine's `claude-code.d.ts`). `gather` ignores them by mtime after an hour, unless a queue is held for them. If the engine gains a delete, `gather` is the place to call it.
- A queue held for a session whose file is gone (older than 1 h, no queue at the time) cannot be reached through the `queue` tool, as the session is not on the board. Only reachable by editing `queues.json` in the bus.
- The `answerLostToast` path (queue and append both failing after a refused submit) has no test.
- `NO_QUESTIONS` is a short list of phrases (Italian and English); another wording of "nothing to ask" still raises a card.

## How to run the tests

From the repo root:

```
claude plugin test .
```

46 tests across `tests/pane.test.tsx`, `tests/request.test.ts` and `tests/rules.test.ts`, about 15 seconds. The harness refuses an `on(...)` registered twice for the same event or after the first `$` call: put hooks (`watch`, `track`, the shared `setup`) at the top of the test. `setup` has a `fault.isNextRefused` switch to make the next `prompt.submit` throw. To prove a test red: copy the changed file aside, `git checkout` it, run the tests, copy it back.
